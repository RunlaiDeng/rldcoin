## Authority and carriage

`Reconfigure` plan in a normal block. Three original old BFT signing journals
then persist their irreversible fences, while three explicitly pinned fresh
new candidate journals approve that exact selected handoff. Both ordered sets
of native signatures are required before activation. New ordinary prepare and
commit voting still requires three distinct admitted validators. Old unanimous
epoch admission retains its four-old/four-new threshold; legacy BFT has no
epoch activation.

The ordinary supplemental lifecycle can exchange typed `EpochApproval` and
`EpochActivation` bodies through the pinned ground TLS mesh. `EpochSigned` and
`EpochSubmission` carry complete epoch proofs for the first new-era proposal
and owner request, before a finalized new-era checkpoint exists. Native wire
reconstruction and full native evidence/epoch verification happen before Python
sync, body deduplication, ledger changes or signing. A digest or advertisement
never authorizes a membership update, ledger or key.

Distinct fully verified three-signature subsets may certify the same exact
native epoch statement, selected block and replayed closing ledger. Every
received variant is authenticated; original retained proof and journal bytes
remain unchanged. A valid duplicate body cannot hide an invalid later envelope.

epoch events at their closing boundary before accepting a new-era suffix.

## Explicit configuration and separate custody

`RLD-REGIONAL-BFT-NODE-JOINT-V1` requires the normal node configuration plus one
`joint_epoch` intent: four ordered disjoint fresh keys mapped to explicitly
pinned existing carrier identities, one selected height, the local new key file,
new native voting directory, separate candidate approval directory, and separate
caller-head files/directories. Discovery never supplies endpoints, certificate
pins, key rights or a configuration update. This is one preconfigured transition,
not an arbitrary overlapping membership service.

Old voting, new candidate approval and new voting journals have independent
caller heads. Each caller persists the exact pending review before native
signing and retains the advanced head/outbox before response release. Restart
uses exact native recover-only; an unchanged head may clear an unsigned pending
review but cannot release an existing debit, reservation or fence. A latest
external head refuses an older signer backup. Common rollback or copied-key
concurrent custody remains unqualified.

A new voting journal starts only at the fully installed native activation
boundary, with an exact matching handoff already authenticated in its local
candidate journal and pinned by its separately retained caller head. Receiving
historical boundary evidence cannot create a late observer's signing custody.
Its exact native creation observation is separately retained before
creation; an interrupted empty journal must match that observation and key
binding. Existing journals without the retained marker refuse. Missing journals
after the boundary remain read-only. Retained old and new responses are recovered
before comparing their independently retained current heads.

and installed epoch events from genesis through the same native event execution

infers a missing local epoch event from remote evidence. Historical ownership,

real native owner-signed payment. Its controller does not construct consensus

must distinguish the actual observed sample from controller-carried V29 tests.

handoff, cold catchup, restart and actual payment inclusion.
