## 模型输入与边界

`tools/value_composition_model.py` 接续旧单单位模型，旧文件和证据保持原样。
模型开始于已认证兼容起源历史的一部分已发行资产；未触及资产在守恒两边
相消。它没有新发行授权，不以示例金额替代 §6 的精确发行实现。
实际 cap=10^35、u128 加法和 u64 高度检查保留；小金额只是搜索输入。

模型假设所有者授权、已准入终局、完整来源闭包和事故对已由理想 oracle
认证。布尔参数是数学前提，绝不能成为原生 API 的验签替代。
操作的全序只是因果 DAG 的一个线性扩展，不要求宇宙同步时钟或在线地球目录。
模型没有运输、签名保管、跨设备、并发落盘、旧备份或密码验证。

128 节点、512 输出、128 深度、16 输入/依赖 fanout 是**模型搜索边界**，
不是新增采用参数，不修改既有原生 8 MiB/256 块/64 检查点/4096 索引限额。
4 步搜索只穷举相应前缀；2016 块挑战边界另有明确轨迹，搜索中的 W=1

## 互斥账与完整谱系

每个历史节点保留唯一输出 `(node,index)`、完整正整数金额、地区、所有者、
成熟高度和所有前驱的完整并集；值输入和非价值证明引用分开。
每个值输入在兼容选中历史内只消费一次。证明引用本身不消费或创造金额。
恢复检查从全部历史重建存活输出、已消费 ID、深度和谱系，不信任状态索引。
不支持的、前向、自指、缺根、重复消费或丢失祖先的历史拒绝。

U 是所有当前输出，包括未成熟/隔离输出。E 是活通道容量和精确挑战费储备。
T 是选中来源里未唯一导入的出口总额，包含尚未终局的扣款。
历史已导入出口、事故记录、已消费 ID 和证明节点不再成为资产。
三个桶的对象 ID 必须互斥，而且必须精确覆盖所有选中未消费输出。

对任意已通过上述前提的状态，逐转换保持 I=U+E+T：

| 转换 | 消费与产生 | 桶的净变化 |
| --- | --- | --- |
| 付款/拆分/合并/找零 | 输入总额=所有输出+具名矿工费用 | U 内重分配，I 不变 |
| 出口扣款 | 输入=出口 gross+找零+来源费用 | U 减 gross，T 加 gross |
| 出口终局 | 认证准确现存扣款及其闭包 | 无金额变化 |
| 唯一导入 | 消费准确 T 对象，gross=收款净额+目的费用 | T 减 gross，U 加 gross |
| 通道资金 | 输入=容量+找零+资金费用 | U 减容量，E 加容量 |
| 挑战储备 | 准确容量原值承接+所有者费用输入，产生原值容量和储备 | U 减储备，E 加储备 |
| 关闭/支付审阅 | 准确状态、全部授权、储备和 c+W 边界 | 无金额变化 |
| 挑战 | 原值容量+储备=原值容量+矿工费用+显式费用找零 | E 减已用储备，U 加等额费用/找零 |
| 结算 | 容量+未用储备=双方精确支付+储备归还 | E 减全部，U 加等额 |
| 有效事故 | 保留证据和全部负债，仅限制新转换 | U/E/T/I 均不变 |

每种生成输出的转换由同一 `_node` 检查精确输入总额和输出总额，随后独立
历史扫描核对全局活对象和桶。各项金额非负且和不超过 cap，故 u128 中间和
不会溢出；边界输入仍检查，不能仅以 Python 大整数代替执行宽度。
初始 I 守恒与每步零净发行组成对任意有限成功轨迹的归纳论证。
这不证明 oracle 正确、原生实现 refinement、共识安全或无限执行资源。

## 污染闭包与挑战费

每个新输出，包括矿工费用、找零、退回储备、双方结算以及承接的容量，
都取得整个输入谱系并集。每条边指向已存在的前驱，所以沿图传递不会出现
自认证的环。地理返程仍产生新扣款/导入节点；原出口不退款。

挑战费分配必须承接原通道容量及其准确状态，不可改变容量、双方、既有状态
或释放旧消费 ID。模型的承接容量和储备共同继承完整输入并集。
如果先干净的容量接入争议费用谱系，**整笔容量也受污染**；不能仅冻结费用。
该规则须通过新的明确原生采用合同实施，不能自动改写旧 Earth 或地区 profile。

事故使依赖该地区的全部输出、容量、储备和待导入出口保持负债但不可继续
支付、关闭释放、挑战、结算或导入。模型没有解除隔离入口。没有预采用解决
权限和守恒状态转换时，隔离永久保留。无关已证明谱系仍能支付。

无钥重复导入仅返回同一结果；回执、失联、时间或记录丢失均没有退款转换。
模型另允许一个**孤立的最后未终局来源出口**原子撤销：保留原历史对象，将
该选择标记为 orphaned，移除尚未消费的找零/费用并恢复原输入。已有终局、
导入、费用消费或来源后继时拒绝。一般完整分叉后缀仍须另做重放模型与原生验证。

本轮 12 个行为场景通过，包含所有小整数拆分/合并/费用分配、真实 cap 边界、
未终局/不完整/错目的导入、重复信用、孤立尾部、三地区返程、混合通道和储备、
精确 2016 挑战边界、使用/退回费用、事故前后及无关谱系付款。
四步前缀穷举完成 6999 状态/11656 转换，所有成功状态满足独立重建检查。
不变量失败是独立异常，不能被搜索器当作正常操作拒绝而静默漏掉。

实际执行的坏模型分支拒绝：给未交付出口退款；再次加入已导入输出；
删除费用/承接容量的争议祖先；自指或缺失来源。正常模型保留两张事故证据，
阻止事故后的新转换，而非扣除或重新发行已有金额。

另一条实际反例保留：完整事故前备份仍通过全部图/金额重建，并能在未见事故的
旧视图关闭通道；保留事故的当前状态拒绝同一操作。因此上述守恒论证**不证明
新鲜度**。原生实现必须另需存活独立最新状态/调用者见证；不能从旧备份重建
本机 head 或重新初始化见证以授予签署权。没有该前提时只能保留/只读，不能
将“完整冷重放”称为旧备份可支出。模型现没有独立新鲜度实现，反例保持成立。
