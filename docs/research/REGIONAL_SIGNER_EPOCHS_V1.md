# 地区签名锁与验证者时代交接候选

通用地区候选源码修订 3，对应白皮书 1.10 的 I7，部分 I5/I9/I10。
这是另行启动的公开 fixture 候选：无货币价值，不升级已签网络，也不迁移旧币。
新源码身份产生新的 fixture 币根；一次候选内部的验证者交接则保持原币根、
地区、历史和余额，不建立替代发行。

## 原四签配置的终局规则

继续要求四位有序验证者全部签署检查点。这里实现的是追加式挖矿历史、持久
签名锁与共同交接，不是容忍缺签的 BFT 共识。缺少任何一位旧或新验证者的
交接签名时停止采用，没有降低门槛、超时替代或全宇宙实时投票。

Statement 新增 validator epoch 承诺，签名同时绑定币根、地区、检查点高度、
块/状态根和前一检查点。初始时代 ID 绑定地区及创世准入的四把验证者键；
后续时代 ID 绑定交接声明。Snapshot 必须携带到自身时代为止的完整有序
交接证明，不能依靠接收者已经缓存的信任省略证明，也不能提前声称未来时代。

交接声明绑定币根/地区、递增时代序号、前时代、最后旧时代检查点 ID/高度，
以及新的四把有效有序键。新集合必须不同，允许成员重叠。关闭锚包含旧签名
和完整的已挖 Header 前缀；本地安装还必须找到已完整价值重放的同一检查点。
关闭点必须是本机已安装终局的精确链尖；旧、新集合分别四签同一交接声明。
关闭高度仍属于旧时代，只有之后的高度可由新集合签署。离线接收者先重放
关闭检查点和依赖，再验证共同交接与新检查点，无需向地球或签名服务查询。

每次本地交接作为独立 Journal 事件落盘，重启核对当前时代、关闭点和高度。
交接只改变签名权限；UTXO、发行累计、历史扣除、导入去重与费用全部保留。
旧历史证书仍按其高度及原时代验证，旧密钥不能授权交接边界之后的新证书。

## 持久签名入口

每把键使用独立 Agent 目录及 OS 独占锁。signer.json 只存公开绑定、请求与
已释放签名，不能存私钥。初始化必须是新绝对路径；已有授权键不能在本机
存在终局之后新建空目录替代原签名历史。新候选成员可提前建立独立目录，
但未共同同意交接就不能签新时代检查点。

每次请求必须来自已完整重放、通过当前事故策略的 Store。签名者额外核对
实际挖矿前缀、命令承诺、时代权利与关闭前缀。下一检查点必须严格增长，
延伸已有签名前缀，且 previous 精确等于自己签过的前一检查点。新加入者
必须延伸其同意的关闭前缀与关闭检查点。旧签名者只能对自己已签过的精确
关闭点签交接；一旦交接签名落盘，旧时代即封闭，即使全套交接尚未安装也
不能继续签旧检查点或第二份相同前时代的交接。继续担任新成员的同一键，
可以对同一交接重取签名，之后签新时代。历史最多保留 128 个签名请求。

签名在内存产生后，先写新 Journal、fsync 文件、原子 rename、fsync 目录，
再返回 Approval 和 lock_head。持久化失败不释放签名，并停止本进程的后续
签名直至重开。精确最后请求可在重启后用最后请求的前 head 或当前 head
重取同一已落盘签名；不同请求不能利用此重试例外。

调用者每次必须提供**另行保留的** expected-lock。它是整个有序 Journal 的
哈希；返回的新 head 必须由调用者保存以供下一次请求。恢复旧 signer 备份
而保留较新外部 head 时拒签。signer-status 的本地 head 不是独立外部锚，
不能自动读取它并声称完成防回滚。实测 helper 将 head 保留在签名目录之外，
每个签名调用都是新的原生进程；这仍是同机同控制者，未构成独立单调设施。

密钥输入为另行保留、非符号链接的最多 256 字节 JSON（secret_key 为 32
字节种子的 hex）。Unix 权限不得向组或其他用户开放；实际公钥必须等于
绑定键。CLI 不接受命令行私钥，不保存密钥，也不在结果/错误中输出它；
缓冲采用 zeroize。密钥硬件、独立保管、恶意文件系统写入和硬件掉电资格
没有由这些软件检查证明。

## 故障和保全

同一前时代的两份不同而各自旧/新签名齐备的交接，构成认证事故；其关闭
区块完全相同也不能隐藏信任分叉。旧时代证书越过共同交接关闭高度，也是
认证事故，即使块前缀相容。事故 ID 同时承诺检查点与交接声明的有序上下文，
不依赖签名 hex 大小写。已存在的 Header 分叉认证规则继续适用。

本地 install-epoch、finalize 和接触 evidence 在对应验证范围发现这种事故
时持久保全。所有证据都要先验证完整时代权利；无效新键、缺签或伪造交接
不能冻结。事故继续采用修订 2 的 pending guard、独立 proof 文件、依赖隔离
和精确恢复规则，不采用冲突分支、不退款、不解除原隔离。候选时代交接不
解决已经发生的事故，也不授权补偿或自动复活被隔离的地区。

全部签名目录、账本目录及外部 head 同时回滚、复制密钥绕过 Agent、伪造
底层 fsync 成功等超出当前防护。Ledger 自身仍缺跨设备外部单调恢复锚。
更换验证者键也不是更换密码算法或解决长期在途证据的撤销问题。

## 命令与检查

每条 CLI 都需 --dir、--authority 和精确 --currency。

- signer-init --signer-dir DIR --key PUBLIC_KEY：初始化空锁，返回需另存的 head。
- sign-checkpoint --signer-dir DIR --key-file FILE --expected-lock HEAD：
  签署本机实际 unsigned Snapshot；返回签名、旧/新 head 和 request ID。
- propose-epoch --validators FILE：从精确安装的链尖构造 unsigned Transition。
- sign-handoff --signer-dir DIR --key-file FILE --expected-lock HEAD --file FILE：
  对无新旧 approvals 的交接请求签名，先封闭前时代。
- install-epoch --file FILE：安装汇集齐备的新旧 approvals；不改变货币余额。
- signer-status --signer-dir DIR：只读重放锁状态；不可当作独立防回滚设施。

35 项原生测试包含旧行为及签名重启/重取、旧备份加新外部 pin 拒绝、分叉、
错键、独占锁、损坏 Journal、写失败无签名、缺签/错误序号/错误高度、轮换
重启与守恒、完整时代运输、第二次含重叠成员的交接、共同信任分叉、以及
越过关闭边界的旧时代证书保全。严格全目标静态检查通过。

128 次原生 CLI 调用的三地区 campaign 对**所有正常检查点**使用持久签名
Agent。地球先完成旧时代终局，测试旧签名备份拒绝，再由 2–5 与 62–65
公开 fixture 键共同交接；新签名终局的出口经相邻地区离线验证，完成既有
多来源付款、再出口和新返程。守恒、比邻星事故隔离、74 个受影响返回单位
保留、无关本地付款和损坏 proof 精确恢复继续检查。没有真实私钥、独立
运营者、真实物理链路或长期时间/寿命证明。

四签缺签时的停顿是一项明确限制。完整 BFT 的锁/视图/故障恢复及重配置仍
需另行实现和资格；例如 [HotStuff 原始论文](https://arxiv.org/abs/1803.05069)
和 [PBFT 原始论文](https://www.usenix.org/conference/osdi-99/presentation/practical-byzantine-fault-tolerance)
所讨论的共识假设和活性机制不由本候选实现。I7、I10、I11 和其他 I1–I12
仍未完整达标。下一步继续接入原生邻居接触的自动证据提交与钱包当前签前
核对，并保留 BFT、通道、长期档案/密码和独立资格门槛。

## 修订 13：明确准入的容错地面配置

新 `RLD-REGIONAL-BFT-FIXTURE-V1` 规则必须在 authority 签名的 Admission 中
明确采用。`contact-fixture bootstrap --bft` 只生成新的无价值 fixture 根；旧
四签准入不能解释三签证书。四位等权验证者、最多一位拜占庭故障是本配置的
设计假设。地面控制器演练验证部分安全/恢复行为，不是该假设下的完整证明。

投票域分别绑定币根、地区、时代、已认证父检查点、父高度/块/状态、目标值、
轮次与 Prepare/Commit 阶段。每阶段需三至四把严格排序且不重复的当前授权
公钥，逐一验签；准备票不能当作提交票。普通完整价值重放先验证奖励、实际
所有者、永久扣除/导入和祖先证据，之后才允许投票，不能签余额摘要代替块。
检查点只推进一个区块，完整区块与对应终局在同一原生 Journal 提交中安装。
无证书 `mine`/直接接受、旧四签 `sign-checkpoint` 与混用证书均拒绝。

每位验证者使用独立私有 BFT Journal 和独占目录锁，每轮最多准备一个值。
提交前必须已准备同一值并验证同轮准备证书；准备证书锁随提交记录先 fsync
落盘，再释放签名。轮次前进保留此锁。超时声明有签名，报告已锁准备证书；
换轮须三方声明及正确的前一轮，领导者按父高度与轮次确定。新提案须重提
认证换轮证书中最高准备轮次的值。不同值只能凭比自身锁更新的有效准备证书
通过准备检查；单独超时不能解锁。无三方证据就停止，不制造收款/退款。

每次调用者提供另存的最新 head；旧 BFT Journal 加保留的新 head 拒签。
已保留的精确请求可以无密钥重取原消息，即使其轮次已封闭；这是已有签名
恢复，不是新的旧轮投票。`--recover-only` 没有对应保留请求时不能首次签名。
重启重放请求、实际父历史、确定性锁转换和全部签名；中断 `bft.next` 仅接受
原 Journal 的精确一条扩展。写失败不释放新签名。全状态/head/密钥一并回滚、
复制密钥、恶意存储和独立单调设施仍无资格，签名状态必须私有保留。

新增八项原生检查覆盖三签两阶段实际入块、少数/重复/错域/错阶段/错轮/错
签名、持久锁/封轮/旧备份/精确恢复、无证书入账拒绝与合法不同三签子集、
持久化失败/中断恢复，以及超出故障假设的冲突证据保全和不退款隔离。还
穷举三位诚实验证者收到故障初始领导者两种不同提案的八种分配：有效准备
证书锁进入三诚实方的换轮证明，故障领导者停用后其余三方重提并提交。

`tools/regional_bft_campaign.py` 使用每地区四个独立原生账本目录和私有签名
目录，每次签名/安装/状态读取都是新的 CLI 进程。初始领导者不投票，其余
三方认证换轮并推进；离线副本只靠逐个认证区块追赶。实际钱包完成地球到
比邻星净额 95，再转仙女座净额 93；远端执行期间没有地球调用。接触证据
先被验证并保留，不能直接计为到账；目的区三方认证导入，按当地高度成熟。
重复运输及重复 Import 不再记账。守恒只计算每个地区一份规范历史，不能把
四份副本当四倍发行。报告另列所用币根/源码根、实际调用和未完成资格。

现有命令是 `bft-context`、`bft-init`、`bft-status`、`bft-candidate`、
`bft-sign`、`bft-quorum`、`bft-timeout-certificate` 与 `bft-certify`；
最后仍须 `finalize --file` 原子安装。候选目录须新建，head 另存，私钥只从
既有严格权限文件读取。投票 Journal 最多 128 条、每高度最多 32 轮，保留
原 64 检查点、256 区块等限额；到达容量停止，不删除旧投票后继续。

自动 pacemaker、投票传播/重传、持续故障网络、独立验证者运营及完整容错
时代交接尚未实现或资格化。当前容错 `propose-epoch`、手工旧式交接安装与离线交接证明验证均明确拒绝，
包括签名完全有效的旧新全四签交接，不能把它直接当成容错重配置。旧配置继续原交接规则。基础研究
可参照 [The latest gossip on BFT consensus](https://arxiv.org/abs/1807.04938)，
但本有界候选并非该论文协议的完整实现，也不继承其证明。I7 仍未完整达标。

## 修订 14：普通节点生命周期中的自动地区共识候选

`--bft-config` 将显式准入验证者的私有配置接入普通原生节点及中继生命周期。
Python companion 自动调度提案、准备、提交及认证超时；Rust 独立验证完整
原生父历史、价值、轮次、锁和每条签名，签名仍由持久原生 Agent 产生。
普通中继不会因地区广告、转发消息或启动节点获得验证者资格。配置必须精确
映射四位已准入公钥与四个独立 mesh 身份；物理端点/TLS pin 仍由接触配置给定。

调用者 head 目录与签名、账本和 companion 目录分离并独占。签前先保存精确
请求，原生落盘后先推进 caller head，再保存公开响应并清除 outbox。重启只
重取已有签名；无签名且原生 head 未变的待定请求可清除，但不能首次签名。
签名目录旧备份加保留的新 head 拒绝。缺私钥时只继续运输和认证追赶。原生
保留的公开消息可以恢复 companion 丢失的发送缓存；不公开私有 Journal。

控制消息独立于支付消息：完整验证的地区共识 envelope 只绑定本地区，外层
export_id 仅作载荷哈希；它不是付款出口、到账或投票授权。实际源付款命令
经 bft-submit 持久入队后仍未扣账；原生签名/金额/输入验证通过才能成为候选，
完整准备和提交证书经原子 finalize 才安装区块及终局。候选不会重写所有者
签名、有效高度或因运输超时退款。原生已验证 pending import 也须同样认证。

本地超时不作废迟到的完整旧轮证书。运行时对同一父历史的各有界轮次寻找
完整证书，即使已经换轮或移除私钥，仍交由原生验收，且不补签。新本地
阶段成功持久化后留出传播时间；每轮原生一次投票约束限制续期次数，陌生
消息不能续期。真实物理联系和容量始终是进展前提。

原生 bft-network-check 只验证，不改变账本；bft-sync 逐个安装有效认证前缀，
不能用未认证块或目录中间状态代替。合法不同三签子集对同一声明/原生价值
可合并，不能把证书字节差异当作终局分叉。真正冲突仍须保全并隔离。

逐跳成功回执优化仅是临时重传缓存。必须先验证固定邻居签名、连接挑战、
两个 nonce 和精确交换哈希，完整本地回复落盘后才抑制重复逐跳发送。每
64 次尝试、重启或缓存满载都会重新探测；证据一直持久保留。丢失回执、
拒绝保管或本地落盘失败不会停止重试，不产生目的收件/到账/退款。

自动运行依然有严格限额和显式 fixture 暂停高度；具体字段、权限、命令与
限额见[原生命令说明](../../tools/regional-ledger/README.md)。当前只补齐地面
自动调度与传播代码；持续故障、完整活性、容错时代交接、跨区自动价值
端到端资格、独立保管/运营、外部单调恢复与真正物理路线仍未完成。
