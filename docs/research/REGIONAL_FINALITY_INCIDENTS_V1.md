# 地区终局事故：认证证据、依赖隔离与恢复

以下记录修订 2 的证据；当前修订 3 另见[签名锁与时代交接](REGIONAL_SIGNER_EPOCHS_V1.md)。

通用地区候选 V1 源码修订 2；对应白皮书 1.10 的 I7 与部分 I9/I10。
修改实现会产生新的 fixture 币根；不升级既有正式/测试网络，也不迁移余额。

## 可以证明的事故

Conflict 携带同一已准入地区的两份 CertifiedHistory。每份绑定货币/地区、
检查点高度、块与状态根、前一检查点、四个有序有效签名，以及从地区创世到
签名检查点的 Header 前缀。逐头检查父哈希、高度、币根、地区、有效矿工键和
实际 fixture 工作，末头块/状态根必须等于签名声明。两份认证前缀在共同高度
内存在不同块，才构成冲突；兼容前缀、失序签名、错币根、错区、缺签或中继
篡改不能冻结。高度不同的检查点也能证明深层分叉。

这里只认证签名者承诺过不兼容历史，不宣布两条账本都通过了价值重放。即使
签名者签过无效状态，签名安全假设也已破坏，不能靠选择看似正确的一条隐藏
事故。事故 ID 仅绑定按 statement ID 排序的认证对，签名十六进制大小写等
等价运输编码不会多消耗事故名额。

`evidence` 和 `finalize` 在拒绝相冲突价值档案/采用前自动保全有效事故；即使
两份冲突同时首次到达、当地尚无该地区检查点，也能保全。独立 `incident`
入口支持携带事故，`incidents` 返回保留证据。任何这类操作都不导入余额，
不采用冲突分支，不倒扣已接受账本。缺失祖先、旧但兼容证书或无效签名没有
足够事故证据；仅按普通验证错误拒绝。

## 隔离范围

Safety 将认证地区映射到持久事故 ID。若当地地区本身的终局相冲突，新块、
付款/导入/再出口和检查点签署/采用入口停止。若是远方地区，只拒绝新导入
依赖它的出口，以及当地输入依赖它的新付款/再出口。检查覆盖直接来源与
已保留的祖先检查点，不能通过导入第三地区、合并金额、费用或新出口洗掉。

已有 Coin、成熟高度、Import tombstone 和历史 Export 保留原样；没有退款、
自动回滚或把历史出款追回。Status 分开返回 quarantined_regions、incident_ids
和 exposure：受影响当前币、金额、历史出口及金额。历史出口金额包含已送达
与未送达，不能用作“当前亏空”或实际损失估计。外部地区尚未接触事故时可能
已继续支付；本机发现不能瞬时停止全宇宙，也不证明既有敞口可以追回。

不依赖事故来源的当地余额仍可收付、出块；矿工、地区身份和发行授权不因
收到事故转移给中继。保留检查点档案、余额和守恒核对与付款资格是不同结论：
恢复程序可以重放事故前已接受历史，当前新操作必须再检查隔离策略。

## 持久化和安全失败

每个 Store 除追加事件 Journal 外，另有最多 16 份独立事故文件和已预建的
32 字节 INCIDENT_GUARD。确认事故后先 fsync 精确事故 ID 到 guard，再持久
保存完整证据、fsync 文件/目录，然后将 ID 纳入原子 Journal，最后 fsync
清零 guard。守护失败、部分文件、缺证据、错误 ID、目录/文件不安全或容量
超限均停止本进程；重启不把未保存的已知事故当作无事发生。

启动完整验证所有事故文件并核对 Journal 中索引；已索引文件遗失/损坏会
拒绝启动。若 guard 指向有效已保存的孤立证据，可补全索引，保留隔离并恢复
正常服务；guard 指向缺失证据则必须取得那份精确 proof 后恢复。容量满后
保留已有证据与 pending ID，拒绝重启，不能静默丢掉第 17 份已认证事故。

`recover-incident --file FILE` 只恢复 guard 或 Journal 精确固定的认证 ID。
它需要相同币根/信任根和独占锁；完整验证 proof 后补回证据。损坏的原文件
移到独立残留文件保全，绝不以恢复为名移除事故或清除隔离。即使某目录里已
存在同名 JSON，仍须验签，不能仅凭 statement ID 声称完整事故已经落盘。

本地受信任目录、fsync/存储硬件假设仍成立；程序不能保证写入失败的坏硬件
记住新数据。整个 Store（含 Journal/guard/事故）一起回滚到旧备份仍缺外部
单调根防护。事故容量耗尽后的可核验归档扩展未实现。未实现事故解决、隔离
解除、补偿、验证者轮换或任何替代发行；它们需新的明确规则、授权与资格。

26 项原生检查覆盖金额/返程原有场景和：不同高度的认证分叉、兼容证书与
篡改拒绝、自动保全、首次同时冲突、签名编码去重、重启持续隔离、成熟输入
及直接构造区块绕过拒绝、跨第三地区的依赖隔离、无关地区进度、guard 缺失
proof、错误恢复 proof、损坏/伪造同名文件、事故满额与重启安全失败。

三地区 CLI campaign 共 67 次独立进程调用。完成真实候选返程后，注入比邻星
四签矛盾前缀；地球自动保全并经相邻步骤传播给比邻星和仙女座。地球返程的
74 个 fixture runlai 保留并隔离，受影响成熟付款被拒；地球不依赖比邻星的
原生币仍完成付款，仙女座仍出块，比邻星自身停止新块。损坏的事故文件恢复
到同一认证 ID，三个进程重启后隔离一致；每个变更点继续守恒，无增发或退款。

这是同机、公开 fixture 签名钥的有界地面检查，不是独立 BFT、跨设备长期
故障/磁盘掉电或真实星际事故治理资格。I7/I9/I10 仍只部分实现。剩余必需实现包括
地区终局锁/时代与原生自动接触提交、钱包签名前的当前证据核对。
