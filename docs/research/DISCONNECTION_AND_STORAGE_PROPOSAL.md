# 断联准入与长期存储：研究版工程规格

日期：2026-09-28。状态：**提案，未采用、未改变正式创世或运行规则**。依据白皮书 1.5、已签源码承诺 `3dbdc83228ac06049ee077db5c95436273ac6784cfc964bdb678e603669e1974` 和本轮节点/容量核验。

## 1. 必须分开的三个事实

- `endpoint_reachable`：本机目的区能刷新所配置的源 API。现有 `source_fresh` 实质依赖这一事实与最近成功时间。
- `verified_source_anchor`：本地已重放至某个区块，并有已验证、已安装、不矛盾的源终局证书。记录高度、块 ID、证书 ID、前驱与采用身份。
- `remote_observation_age`：远方起源最后可认证的观察时间及时间误差。未知必须显示未知；本地重复刷新、接收中继签名或本机时间推进都不能重置它。即便有起源签名时间，也不能证明没有被隔离于更新消息。

这些字段必须分别展示。没有跨区全局最新状态的可用证明时，不使用“最新全局余额”。因遥远而未知与发现有效矛盾证据应有不同状态。

## 2. 拟议准入状态与转移

| 状态 | 可显示内容 | 拟议准入 | 退出条件 |
|---|---|---|---|
| `BOOTSTRAP` | 固定创世身份及重放进度 | 不受理价值写入 | 所有必要历史、终局和授权验证完成 |
| `LOCAL_VERIFIED` | 本地选定链、远方已验证锚、远方观察年龄 | 按采用规则检查本地已导入资产；新导入仍须完整源证明、终局与唯一 ID | 源端点丢失转断联；有效矛盾转隔离 |
| `DISCONNECTED_KNOWN_ANCHOR` | 同上，明确标示与远方断联/未知 | **待实现和审查**：是否允许已导入余额本地转移及推进区块，要以固定终局锚及独立目的区安全为前提；不得凭新鲜标志允许未验证导入 | 收到新证据后重放、核对前驱、再重新准入 |
| `CONFLICT_QUARANTINE` | 两份矛盾证据、受影响锚和资产范围 | 停止受影响价值操作，不自动退款、回滚已花款或选最晚签名 | 明确事故处理与授权恢复流程；不能由清空告警退出 |
| `CAPACITY_EXHAUSTED` | 资源与拒绝原因，完整旧证据 | 拒收超预算证据，保留旧记录；无静默删除与源退款 | 经过核验的归档/容量恢复，不是删除当前价值依据 |

现有二进制仍执行五秒源端点刷新门槛，断联时余额 API 也受门槛约束。上述状态机不能作为关闭现行门槛的配置指令。源证书只证明其签署历史；对远方已发生但尚未送达的密钥泄露或矛盾签名不能作即时反应。

## 3. 不变量与反例验收

1. 每个出口只在一条兼容目的历史中计入一次；源 U 减少后，未导入金额在 T 中，目的导入后从 T 移至 U。兼容视图内 `I = U + E + T`；不能把不同时间或冲突分支的余额直接相加。
2. 没有回执、过期、队列损坏、断联持续时间及观察节点重启均不能恢复源可花余额。
3. 未安装源终局、缺历史页、乱序前驱、无效签名、目的不匹配均拒绝；重复导入与重复证据必须幂等或明确拒绝。
4. 4/4 签名少一签，新终局不能前进；不同控制者不是进程数量。必须测证书有效但互相矛盾的案例，且用测试专用密钥，不能故意让生产密钥双签。
5. 目的深重组、归档恢复、进程断电后重新核验余额和导入索引。普通成熟不能被写成目的最终性。
6. 离线期间本地新转账的可用性、来源冲突后的影响范围和事故赔付要有完整规格；不能仅让 `source_fresh` 恒为真。

## 4. 存储问题与升级方案要求

已发布的 `MAX_TRACKED_BLOCKS = 100_000` 同时约束源/目的保留条目，分叉也消耗条目。按 600 秒目标估算 100,000 条串行区块约 694.4 天，但实际可能更早达到限制；这不是可运行期限保证。首个奖励时代 200,000 块要求更长历史。现有检查点不裁剪历史，磁盘剩余空间不能解除此条目限制。

优先评估磁盘分段历史和有界缓存：保留每个已采用终局锚所需的完整可重放历史、可审计索引与校验和；区分当前验证热状态、未终局竞争分支和不可变归档。只读缓存淘汰不能改变分支选择或可验证历史。不能把不带历史的余额快照当成自行可验证的检查点。超过限制的运行路径需要实现与新的兼容签名源码授权，保持已有创世、账本和资产身份。

升级接受标准：

- 在合成负载下累计超过 200,000 条选定区块并覆盖分叉风暴；再证明重启、导出、历史同步、源证明与目的重放一致。合成负载只证明资源行为，不能替代真实 PoW 生产历史。
- 用全历史参考实现对照选定链头、累计工作、供应、成熟、通道状态和导入集合；每个归档断点具备可恢复的完整性清单。
- 进程崩溃、磁盘写满、目录损坏、归档失踪/篡改均失败关闭；保存诊断与旧数据，不能启动为空链或产生第二创世。
- 记录峰值内存、磁盘、同步字节量、冷启动重放时间及实际硬件；有明确可承受预算和容量报警。
- 外部复核、迁移演练、回退兼容方案及正式授权后方可部署；现有运行节点不在本提案中被替换。

## 5. 路由预算工具及其边界

`python3 tools/interstellar_route_budget.py docs/research/route-scenarios/mars-blackout-budget.json`

工具从实际外部传输模块读取载荷、帧数和队列字节上限，计算规范 JSON/base64 帧大小；按配置的断联积压、已有队列、可用吞吐、接触窗口、双向光时和假设的成熟时间求预算。每方向一个 FIFO 批次；不模拟竞争路由、联系失败概率或时钟漂移。输入速率须包括下一接触前的全部额外帧；未包括源终局等待、目的区块包含等待、节点重放和重传开销。输出时延是有条件估计，不能称为到账保证或性能实测。

发送后原队列仍保留副本。想长期循环必须另外实现并审查保管确认、归档、删除规则和灾难恢复；本工具不会因为“已发送”腾空队列或退款。三份示例参数均为明示假设：Earth 小批次、Mars 21 天中断每分钟一帧、静止 4.25 光年路线。最后一种即使字节预算合适，回程仍超过 8.5 年；输出始终 `route_qualified: false`。
