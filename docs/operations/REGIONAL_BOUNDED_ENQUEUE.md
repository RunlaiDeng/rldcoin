# 有界消息批次持久化候选

适用于全新私有目录的无价值地面候选。每个普通 BFT broadcast 仍最多选择四个未入队消息/目的对；Native/Core、完整信封认证、所有者审阅、签署/caller head、TLS、收据保管、活动/归档容量及 20/600/300 秒规则保持。

## 实现

`Node.enqueue_batch` 先校验全部 1–4 项 frame/目的/schema/剩余活动容量，再在单个有界副本构造原完整签名 packet 和 receipt-route。所有本地收据仍按原完整认证生成。最后一次原 atomic 发布整个活动状态，成功后才采用内存状态并返回包 ID；没有批次级账本或收据权威。

不合法末项、活动容量或本地收据不足拒绝整批，不发布前面的部分。发布异常必须关闭该 Node；磁盘可能已经完整持久化而返回响应丢失，后续打开仍须完整认证。BFT broadcast 重新核对实际源 mesh 的消息/目的对，已保留整批不会再次入队或签署，也不收回证据。

已完成 Runtime 冷认证的本地不可变消息元数据在 mesh 锁外枚举；选中 payload/frame 仍完整重建与检查。没有待入队项时不改动 cursor，不重写完整 BFT 状态；下次非空选择继续原 cursor。非空批次成功后仍按原四步持久推进 cursor，丢失其响应只能从实际 mesh 去重，不从 Python 缓存授予权利。

## 实际检查

七项聚焦检查通过；随后包含完整 Native caller 恢复、接收去重/篡改、共享活动/归档、真实固定 TLS worker、普通接收和阶段顺序的 110 项相关检查实际通过，32.969 秒。写盘前异常保持原字节，写盘后响应丢失冷开可认证完整批次。真实 Native Timeout 的三个目的包在批次响应丢失后保持原包 ID，重试不增加签署记录、caller head 或 Runtime 字节。

五组交替顺序的同机组件观测使用约 1 MiB 完整地面 payload：四次单项持久发布 0.277–0.292 秒，一次批次发布 0.142–0.187 秒。每个结果均重新冷认证四个完整包，发布次数由四变一。它不是普通付款吞吐、隔离基准或失败原因证明；没有 Native 价值或独立资格。
