# Invocation-scoped Native history signature inputs

One paged signer replay may retain exact successful Ed25519 verification inputs: the complete canonical public key, complete message bytes and exact signature string. An entry is created only after the original strict verifier succeeds. Lookup compares all inputs directly; a digest, file name, height, caller head or serialized ledger cannot initialize an entry.

Each replay constructs fresh, nonserializable witnesses owned by that invocation and thread. Nested invocations begin empty and restore only their caller scope when they exit. At most 64 entries and 1 MiB of input bytes are retained per invocation. Eviction, absent witnesses, borrowed entries and oversized inputs fall back to the original verifier. Failed verification never initializes a successful entry. These limits bound retained input payloads, rather than total process memory, and do not change any ledger, transport, record or archive capacity.

Reuse is enabled only during actual Native record execution. The scope switch is independently owned by its guard, so leaving that range restores the switch even while retained entries are borrowed. Signer request proofs, prepare quorums used by historical signer Commit requests and outer signer approvals continue to perform their original independent strict verification. New requests receive the original proof and value checks before private-key use. No witness survives a new signing call, cold process or recovery invocation.

Every Native record still executes from authenticated signed genesis. Currency and admission identity, validator membership, role, quorum size and distinctness, epoch, context, predecessor, value execution, owner authorization, permanent import records, incidents and signer locks retain their original checks. Complete current bytes, durable publication and independently retained caller heads remain mandatory. Reusing a fixed-suite cryptographic predicate does not cache any of these decisions or supply a ledger initializer.

The public material cache separately performs the original Core canonical encoding, curve and prime-order subgroup checks on every material miss. A signature-input hit still passes public material and signature decoding. Witnesses use the same fixed Ed25519 verifier within one invocation; they do not select or adopt an alternative suite, role or epoch.

Source cases compare exact results with the original Core verifier for changed messages, keys and signatures; valid outer paths remain strict after native scope exit. Additional cases exercise fresh and nested invocations, unwinding, held-entry borrow during exit, entry eviction and byte capacity. Native regressions retain independent cold replay, complete signature and owner journals, invalid later proofs and failure atomicity. Full library, full fault profile, long history, independent custody, suite adoption and physical routes remain separate qualifications.
