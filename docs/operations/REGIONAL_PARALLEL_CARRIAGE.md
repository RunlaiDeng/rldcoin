# 普通区域节点的独立有界出站运输候选

只适用于新私有目录的无价值地面候选。Native/Core、签署阈值、锁、caller head、20 秒基准和原 600/300 秒观察关卡保持；它不是旧失败付款的恢复、采用网络升级、持续 BFT 或物理路线资格。

## 实际缺口

发送 ID 环的冻结付款周期在高度 11 的第三笔付款关卡失败。停止 Native 检查认证了三份第六轮 Commit：节点 2/4 的已到达其他节点，节点 3 的四个目的包仍全部留在其源端活动队列，没有目的收据。节点 3 最后一次普通搜索只有两个 Commit，随后在该 tick 签署了自己的 Commit；最后 TCP 阶段约 0.000031 秒。停止信号可停止 TCP，但已进行的本地认证/签署仍会完成。停止留存的三个票不能追溯为截止前证书或付款通过，也不能唯一归因于运输与账本串行执行。

## 生命周期与所有权

`regional_carriage_worker.Worker` 在 BFT Runtime 的完整冷打开之后，由同一普通 `Service` 默认创建一个出站线程，0.25 秒为地面空闲间隔。它没有 Native、钱包、签署、解码账本或 value 接口；只调用原固定邻居 TCP adapter 的有界 tick。非 BFT 生命周期保持原模式。显式串行 component 检查仍可验证旧阶段顺序，普通 CLI 没有自动回退。

TCP 出站所有权绑定实际线程；重复 worker、其他线程 tick 和重入均拒绝。四个出站联系、四 transit/十六 receipt、原 socket/本地锁/线长/活动与归档容量不变。exact 预备交换先持久推进，然后才打开连接、认证新挑战并绑定请求；关闭 socket 后仍必须实际本地持久保管回复，才允许原临时 hop 抑制。发现不提供新端点、pin、验证者或账本权限。

普通线程仍按原四槽选择、完整认证、Native 同步和签署处理证据。短时 mesh 锁争用最多按既有 0.2 秒锁尝试预算等待；到期仅保留未知运输观测、未处理证据与 seen/cursor 边界，不创造 height、收据或价值。非争用错误和坏签名仍拒绝。BFT broadcast 的四个消息/目的 enqueue 预算没有提高，未入 mesh 的 Native 证据仍必须由普通 broadcast 入队。

## 观测和停止

仅保存一个至多 64 KiB 的完整 canonical TCP 观测；每次读取独立解码。完成次数、时间和失败是诊断，不能恢复 cursor、提供 freshness 或授权入账。没有完成 pass 时明确报告 unavailable，耗时为 null。并行 TCP 不计为串行 contact tick 的 CPU/socket 阶段，`tcp_seconds` 为 null；TCP pass 的独立时长在 worker 观测中保留。死线程或诊断超界导致明确拒绝，不回退到前台或抛弃队列。

停止先阻止新 pass，等待当前本地验证/持久保管结束，再释放出站所有权。TCP 关闭 listener 和 socket 后也等待所有入站 worker 实际退出，之后才释放 service 保管锁。三秒 socket 尝试不能代替本地 CPU 完成上界；控制器的原停止关卡仍可失败，失败目录和原 Native/caller 响应必须保留。这不是断电、跨设备或独立防回滚资格。

## 检查与资格

局部检查使用真实固定 TLS、拒绝错误 pin、单出站所有权、停止期间保留所有权、不可变观测、副本损坏/超界及证据保全。Native component 使用真实提案、Prepare 与 Commit、完整包装和 mesh 入队，在普通 Native contact-status 处设有界观测屏障；先证明确切 Commit 的目的包已入队，再确认独立出站送达。收件 Native 仍为高度零，运输不授予入账。组件测试显式用第二个四项 broadcast 批次排空两个本地票的六个消息/目的对；不是普通调度或完整付款通过。

须另运行新冻结发布构建、完整进程检查、实际 Runtime 保管分支、普通两次交接/三笔付款及完整停止冷认证，之后才可进入成功现场限定的有限缺席演练。持续故障、跨区域完整价值、长历史、独立运营/保管及实际物理链路仍是单独强制条件。
