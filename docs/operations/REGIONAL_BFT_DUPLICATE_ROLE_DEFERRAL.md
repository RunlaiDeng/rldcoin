# 重复信封的角色推进调度候选

正常接收仍先执行完整 `bft-network-check`，同步新认证前缀并核验每份携带时代证明，再按已保留消息体去重。重复消息体随后返回；仅新消息体在该接收操作里推进角色与读取当前状态。正常 tick 在任何签署前读取原生成员集、恢复待处理响应并核对另存 caller head。运输线程不签署。

该调整减少已经完整验证的重复接收再次进入私有角色保管路径，不缓存原生授权，也不跳过证书变体、后续无效信封或新认证依赖。原信封字节、原局部转发标志、全部时代/签名锁和容量保持；局部标志只能在完整认证后提升。

使用新的普通运行源码/编译默认driver与全新无价值fixture。既有359完整故障流程仍失败：原600秒到期后，停止三个Proxima副本在13导入净9、成熟15尚未达到；第四个停12。重复接收的附加调用只是可减少的开销，尚不是该失败唯一原因或普通吞吐证明。禁止扩大原门槛、迁移失败值/私有保管或用停止恢复改判全故障。独立运营、跨设备/掉电保管、长期历史与真实物理链接仍需各自资格。
