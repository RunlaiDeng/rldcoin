# Recover-only quiescence on an explicit local stop

An explicit normal stop of the complete-origin ground companion may reconcile
its retained caller request and response before releasing Runtime custody.
First stop and join the existing outgoing owner and all TCP input, listener and
handler owners. Recovery then runs under the original Runtime and caller locks.
Constructor cleanup, unexpected failures and default close do not request this
step. Legacy, joint-epoch and role profiles keep their existing recovery paths.

Use only the original Native recover-only request under the separately retained
caller head. It cannot first-sign or use a private key. An unsigned request may
clear its pending review only after the original fresh Native signer binding and
exact head comparison. An already retained exact response advances the caller
head and outbox before full Native authentication and durable local retention.
A changed or unknown head, caller write failure or incomplete response preserves
the original pending request or retained outbox. Never infer recovery from a
timeout, diagnostic digest, local stream header or transport receipt.

Quiescence has one shared local two-second Native subprocess deadline, beginning
before transport owners stop. Each subprocess retains the original output and
error bounds and receives only the remaining time, capped by its original timeout.
No failed mutation is retried. Deadline expiry propagates; Native retained
responses and separately retained caller state remain available for the original
recover-only restart path. The wrapper is discarded before Runtime locks release.

No consensus unit, new signature, phase timer, carriage enqueue or owner/value
operation runs during this step. Full local envelope authentication and durable
publication remain required. Python verification, filesystem synchronization and
transport joins retain their existing bounds; a subprocess deadline does not
prove a total shutdown time bound. Ground validation must still satisfy its
original complete normal-stop, cold-envelope, caller/signer and conservation
requirements. Failed stopped scopes remain failed and are never reopened for
replacement qualification.

This is a ground lifecycle candidate, not independent rollback/custody protection,
power-loss qualification, a latency distribution, long-history execution or an
adopted-network upgrade.
