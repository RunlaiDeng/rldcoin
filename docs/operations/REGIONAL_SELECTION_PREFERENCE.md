# 普通接收选择的进程内协调候选

有界入队冻结的第三笔付款在原 600 秒关卡失败。停止检查认证 30 份源 Native 当前消息；15 份目的地已有真实运输收据却未进 Native，包括 Timeout 和 Proposal。原私有字节/权限/属主/链接数不变。这证明运输与 Native 留存有缺口，不能证明全部确切此前选择、到达时序或唯一原因。

## 调度

普通 Service 的实际线程在尝试 selection_node 前向自己的 TCP Server 请求一个进程内选择意图。没有第二所有者。获得 mesh OS 锁并完成原有选择/物化后，先关闭 Node，再清除意图，之后 Native 验证/共识继续独立于原出站 worker。

原 0.2 秒非阻塞锁等待到期仍返回未知，不伪造高度、收据、选择或 seen。此时意图留到同一线程下一次成功选择，防止该进程的 TCP 线程反复抢在它前面重新获得 mesh 锁。TCP 等待此意图与原 OS 锁共用原本 0.2 秒本地尝试预算；到期保留证据并拒绝保管，绝不确认未经实际持久化的回复。正在执行的认证不被取消，其他进程的锁不受此标记控制。

标记只有一个实际 Thread 引用，不写入磁盘、通告、frame、Native 或 caller head。另一线程不能更换/清除它；停止清除标记但仍等待全部真实保管线程退出。非争用损坏/错误释放意图并拒绝，未修复或丢弃证据。

失败选择后的未完成意图可暂时使 TCP 尝试让出机会；它不承诺所有情况下均即时发送。成功选择之后在 Native 检查期间的原独立发送保持。没有上调锁/socket/600/300 秒期限、改变轮次或签署门槛、扩大活动/历史容量、缓存未验数据或迁移失败价值。

## 实际检查与剩余范围

六项聚焦检查通过，2.520 秒：其他线程不能更换意图，原本预算内让出且字节不变；真实固定 TLS 拒绝不产生目的收据和本地抑制，解除后原队列重试才取得完整实际收据；关闭清除意图；真实 Service 的首次锁失败留住意图，后续认证选择清除，Native 日志不变；已入队真实 Native Commit 在成功选择后的 Native 观测屏障中仍以固定 TLS 送达，收件 Native 高度保持零。
