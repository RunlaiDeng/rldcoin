## Model and finite bounds

The storage state machine models one logical operation split across two WAL
records, complete-WAL `fsync`, a rollback-anchor advance, publication, one
checkpoint success/failure, and recovery at every abstract crash point. The
finite value sets contain old/new roots, anchor epochs `0..1`, and these
malformed stable WAL classes:

- truncated record;
- records out of order;
- bad previous state root;
- bad record hash;
- old checkpoint paired with a WAL shorter than its recorded sequence.

The voter state machine models one honest signer and two conflicting proposals
for the same abstract height and round. Its safe order is select proposal,
persist/fsync vote lock, sign, crash, then reload the persistent lock.

The safe invariants require no publication before WAL durability, an extant
durable recovery source for every published state, only complete old/new
recovery outcomes, fail-closed corrupt WAL handling, local anchor monotonicity,
WAL preservation after checkpoint failure, and no second conflicting honest
vote after crash recovery.

## Open rollback gate and limitations

The whole-directory mutation first reaches a complete new checkpoint, then
consistently replaces WAL, checkpoint, rollback anchor, and vote-lock fields
with their old locally valid values. A ghost event records the rollback, but
the local directory contains no evidence that distinguishes it from the
original old state. The expected invariant violation makes this a documented
open mainnet gate: local artifacts alone cannot close it. An external monotonic
witness, independently held checkpoint, hardware counter, remote quorum
witness, or equivalent independent freshness mechanism is required, together
with its own availability and compromise assumptions.

The model does not establish actual `fsync`/rename behavior, torn-sector
semantics, disk-controller guarantees, Rust serialization/decoding, process
concurrency, validator-weight/QC rules, HSM behavior, dynamic rounds/views,
reconfiguration, or recovery/consensus liveness. Implementation anchors in
`TRACEABILITY.md` are navigation points only.
